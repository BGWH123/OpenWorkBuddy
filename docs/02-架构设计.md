# 架构设计

## 模块

```text
浏览器界面
  工具栏、任务列表、对话、模式、专家、技能、结果区
        |
HTTP 接口  127.0.0.1:4186
        |
任务运行
  模式判断、计划确认、工具循环、本地规则或外部模型
        |
工作区
  路径限制、列出、读取、搜索、写入、导入、命令
        |
存储
  工作文件夹中的产物
  data\state.json 中的任务、最近工作区和模型设置
```

界面使用 React。构建使用 esbuild。`Z:` 上的 esbuild 程序不能直接启动，构建脚本会先把它复制到系统临时目录。

## 模式怎样影响工具

| 模式 | 可以使用的操作 |
|---|---|
| 仅问答 | 列出、读取、搜索 |
| 计划，尚未确认 | 不调用工具，只返回方案 |
| 默认，或计划已确认 | 再加上写入文本和在工作区目录执行命令 |

模型即使返回了写入或命令，执行层也会按上表拒绝。本地规则在发起操作前就遵守同一限制。

## 数据流

1. 新建任务时先把用户的话记入任务，状态改为执行中，接口立即返回。
2. 计划模式只追加方案，并把状态改为待确认。确认后才进入工具循环，指令仍使用确认前的那一段任务。
3. 工具循环最多 6 步。写入成功后，任务记录产物路径和变更前后的文本。
4. 界面在有任务处于执行中时轮询状态。文件始终写在所选文件夹里，不写进程序目录。
5. 两个任务的状态更新串行写入 `state.json`，工具执行可以同时进行。

## 本地规则的边界

没有外部模型时，本地规则只识别明确说法：创建或修改某个文件、列出、读取、搜索、整理目录、生成文档、表格或网页，以及「执行命令：」。

它不会查外部资料，也不会把推测写成事实。生成的稿件会写明这一点。外部模型是否编造内容，取决于所选模型；系统说明要求它区分已读内容和未确认项。

## 尚未确认的对应关系

安装包里能看到 ask、craft、expert、quick、design 等模板文件名。当前公开说明里的三种用户模式是默认、计划和仅问答。本版按公开说明实现。craft 是否就等于默认模式，quick 和 design 在界面上如何切换，没有在这次用运行中的 WorkBuddy 逐项核对，不能当成已经证实的结论。
